Why it's different — measured, not claimed

Written in Go, so concurrency is the default rather than the upgrade.

Platforms built on the JVM pay real money for every thread. That cost leaks into the product design: branches execute one after another, parallelism becomes a licensed tier, and the answer to more volume is a larger instance.

Goroutines cost almost nothing, so SHIFT runs branches concurrently because there was never a reason not to. It's the same reason a worker fits in tens of megabytes instead of gigabytes — and the two facts have the same cause.

The platform

Everything an integration team actually needs, and nothing metered.

Visual flow builder

Drag connectors onto a canvas, branch on data, merge streams back together. Every flow is a plain JSON document underneath — diff it, review it, keep it in Git.

Concurrent branching

Fan a stream out to several destinations at once, or route records by their content. Branches genuinely run in parallel, not one after another.

Streaming transformations

Map to a target shape, filter, aggregate, join two sources on a key. Large groupings spill to a single scratch file rather than exhausting memory.

Triggers that fit the job

Schedules that fire exactly once across replicas, inbound webhooks, or a synchronous call that returns the result in the same response.

Secrets that stay secret

Envelope-encrypted with a key per secret. Values resolve on the worker at run time — never in the queue, the control plane, or a log line.

Signed connectors

Every connector is signed by its publisher and verified before it runs. Workers refuse anything that fails, with no override.

Single sign-on

Any OIDC provider — Entra, Okta, Google, Keycloak. No per-vendor integration and no lock-in to ours.

Audit and metrics

Every administrative action recorded and exportable. Prometheus metrics from both planes, with per-step timings from the engine itself.

Workers where you need them

Put workers in your datacentre, your VPC, or both. The control plane never sees your payload data — only metadata about the run.
